# ABSTRACT

Founders and operators who run several early-stage ventures simultaneously face a persistent information problem: the data they need to make decisions is fragmented across many disconnected Software-as-a-Service (SaaS) tools. Engineering activity lives in GitHub, team communication and attendance in Slack, content performance in YouTube Studio, and finance, hiring, and project status in yet more spreadsheets and dashboards. Each tool answers only its own narrow question, none of them are aware of organisational roles, and synthesising a portfolio-wide picture is a manual, error-prone, and time-consuming exercise.

This project presents **Founder OS**, a unified, role-aware operations-intelligence platform that consolidates these scattered signals into a single web application and makes them legible to the right person at the right altitude — from an individual team member up to the founder. The system is built as a single-page application using React, TypeScript, and Vite on the front end, and Supabase (managed PostgreSQL with Row-Level Security, plus Deno-based serverless edge functions) on the back end. A fine-grained role-based access-control model is enforced not only in the user interface through route guards but, more importantly, inside the database through Row-Level Security policies, so authorization cannot be bypassed by a malicious client.

The technical core of the platform is a **generic connector framework** that ingests data from third-party services through serverless functions, normalises it into a common schema, and exposes it through purpose-built analytics dashboards. Three connectors are implemented end to end: a **YouTube** connector using the OAuth 2.0 authorization-code flow to pull channel, video, audience, and retention analytics; a **Slack** accountability connector that reconstructs a configurable "work-day" (with a boundary hour so night shifts are not split at midnight) to track attendance and work updates across an entire team; and a **GitHub** engineering connector that synchronises commits and pull requests across multiple organisations, maps anonymous handles to employees, and surfaces contribution load and key-person ("bus-factor") risk. Layered on top of every connector is **KAI**, a natural-language assistant that constructs a grounded JSON snapshot of the synced data and queries a large-language-model gateway, allowing both engineering leads and the chief executive to ask plain-English questions and receive answers cited strictly from the organisation's own data.

The platform additionally implements email one-time-password multi-factor authentication, a transactional-email queue, and dashboards for project management, human resources, and finance. The result is a working, security-conscious, extensible system that demonstrably reduces the effort required to obtain a cross-functional, cross-startup operational view. This report documents the motivation, a review of related work, the system design and methodology, the implementation of each major subsystem, the results obtained, and directions for future enhancement.

**Keywords:** operations intelligence, role-based access control, Row-Level Security, OAuth 2.0, serverless functions, data connectors, large language models, retrieval-augmented question answering, engineering analytics.
